# mk-plugin-genshin

[mk-go](https://github.com/shiroha-a/mk) のサーバープラグイン。利用者が原神の UID を登録すると、プロフィールに戦績とショーケースのビルドを表示する。

データ元は [Enka.Network](https://enka.network/)。認証不要の公開 API を使う。

   ↓ クリックで開く

## 導入

mk-go は**プラグインをビルド時に組み込む**。`plugins/` に置いてビルドし直す。

```bash
# mk-go のリポジトリルートで
cd plugins
git clone https://github.com/shiroha-a/mk-plugin-genshin genshin
cd ..

make build          # plugins/ を走査して取り込む
```

フロントエンドを持つので、**フロントエンドも作り直す**。

```bash
make uds-frontend-build   # 本番構成 (docker-uds)
# または make e2e-frontend-build
```

そのうえで mk-go を再起動する。**再起動しないと画面が変わらない** — mk-go は起動時に一度だけ manifest を読むため。

```bash
make uds-up
```

> **注意**: 配布されている Docker image (`ghcr.io/shiroha-a/mk`) を pull するだけでは使えない。ビルド時組み込みなので、プラグインを使うインスタンスは自分でビルドする必要がある。

導入の一般論は [mk-go の docs/plugins/operating.md](https://github.com/shiroha-a/mk/blob/develop/docs/plugins/operating.md) を参照。

## 使い方

### この開発版の本人確認・複数UID連携

UIDを入力して「紐づけコードを発行」を押し、コードを原神のステータスメッセージへ追加して保存してください。**一度ゲームからログアウトしてから「認証する」**を押します。Enka.Networkから一致を確認できた場合だけ連携が完了します。

- コードは発行から10分間有効です。再発行すると以前のコードは無効になります。
- Enkaの反映待ち・キャッシュ期限は尊重します。期限は自動延長しません。
- コードは数字と記号からなる合計6文字で、記号を1文字以上含みます。ステータスメッセージにコード全体がそのまま含まれる場合に認証します。
- 1コードあたり最大10回、確認送信後は取得失敗時も最低60秒待機します。EnkaのTTLが長い場合はTTLを優先します。再発行は最低30秒間隔で、再発行しても確認待機を短縮しません。
- `genshinUidLimit`ロールポリシーが本人確認済みローカル連携の上限です。既定1、0は新規連携禁止です。
- リモート連携のpeer cacheと未確認申請は上限にもUIDの占有にも含めません。
- 1 UIDにつきこのサーバー内の1 Misskeyアカウントだけが連携できます。
- 上限引下げで既存連携は削除しません。解除後、別アカウントでも再確認して連携できます。
- 複数UIDはプロフィールに個別カードとして表示します。旧peerプロトコルには先頭のカードを返し、複数カードの連合は別途拡張予定です。
- migration 8は旧版の未確認登録を`accounts_unverified`へ退避します。本人確認済みとは見なさず、UIDの占有や公開表示に使いません。

`POST /me/set`による無確認登録は無効です。新しいAPIは`/me/begin`、`/me/verify`、`/me/unlink`です。確認時の`code`は現在の申請と一致する必要があり、他ユーザーの申請や使用済み・期限切れのコードは利用できません。

ゲームアカウントのステータスメッセージを変更できることの証明であり、法的な本人確認ではありません。プラグインのDBを管理者が直接変更できることまで防ぐものではありません。

利用者が **設定 → プロフィール** で UID を入力する。9〜10 桁の数字。

本人確認時に取得してコードの一致を確かめます。以後は10分ごとのジョブが期限切れの情報だけ取り直します。取得できない場合やコードを確認できない場合は連携を確定しません。

表示するには、ゲーム内で**キャラクター詳細を公開**しておく必要がある (プロフィール → 「キャラクター詳細を公開」)。飾っていないキャラや非公開のアカウントでは、名前と戦績だけになる。

プロフィールでは既定で**ラベル 1 行**しか出さない。他の情報と並ぶ場所なので、開かないうちは縦を占有しない。

## 設定

省略できる。既定で動く。

```yaml
# .config/default.yml
plugins:
  genshin:
    enabled: true
    endpoint: https://enka.network      # 取得元 (テスト用に差し替えられる)
    userAgent: mk-go-plugin-genshin/0.1 (+https://github.com/shiroha-a/mk)
    timeoutSeconds: 10
    language: ja                        # 名前の言語 (loc.json の言語コード)
```

`language` は `en` / `zh-cn` / `ko` などに変えられる。指定した言語が無ければ英語に落ちる。

## 表示する情報

Enka から取れるものは一通り出す。

**プレイヤー**: ニックネーム / 自己紹介 / 冒険ランク / 世界ランク / サーバー地域 / 達成実績数 / 深境螺旋の到達階と星数 / 幻想シアターの到達幕と星数 / 好感度Lv10 のキャラ数 / 名刺 / プロフィール画像

**ショーケースのキャラ (最大12体)**: レベル / 突破段階 / 命ノ星座 (アイコン付き) / 好感度 / 天賦レベル (星座による強化を `+3` で併記) / 実数ステータス16項目 / 武器 (名前・レア度・レベル・精錬・基礎攻撃力とサブステ) / 聖遺物5部位 (セット名・レベル・レア度・メインステータス・サブステータス4つ)

## リモート利用者

**同じプラグインを入れた mk-go 同士**なら、他インスタンスの利用者のプロフィールにも戦績が出る。相手のインスタンスに取り寄せを頼む形で、経路は mk-go 専用の peer channel (ActivityPub には出ない、mk-go #2537)。

- 相手が同じプラグインを持たなければ何も出ない (Misskey TS などが相手なら常にそうなる)
- **問い合わせは非同期**なので、初めて開いたときは出ない。少し経ってから出る
- 取り寄せた分は 30 分覚える (相手も Enka の ttl を待っているので、頻繁に聞いても新しくならない)
- 相手に送るのは **username だけ**。誰が見に来たかは送らない
- 相手が返す画像 URL は、こちらのプロキシ経由に貼り替える (CSP と、閲覧者の接続先が相手に漏れるのを防ぐため)

相手側は「自分のところの利用者」の分だけ答える。手元にキャッシュしている他所の利用者を又貸しはしない。

## 取得元への配慮

Enka.Network が[利用条件として挙げている](https://github.com/EnkaNetwork/API-docs/blob/master/api_ja.md)ことを守っている。

- **`ttl` を必ず待つ。** 応答が返す `ttl` 秒はキャッシュから返し、期限が切れたものだけ 10 分ごとのジョブで取り直す
- **`User-Agent` を名乗る。** 既定でもインスタンスが分かる形で送る
- **UID を列挙しない。** 取得するのは利用者が自分で登録した UID だけ

画像は Enka から直接読まず、**同一オリジンで中継**する (`/api/plugin/genshin/asset/<name>`)。mk-go の CSP が `img-src 'self'` なので、緩めずに表示するため。中継したものは 1 日キャッシュする。

## 開発

```bash
cd plugins/genshin && go test ./...
```

外部に出ないテストだけで完結する (Enka とマスターデータは `httptest` で差し替える)。

**踏みやすい罠**をコード中のコメントに残してある。

- **値の単位が 2 系統ある** — `fightPropMap` (キャラの実数ステータス) の割合系は 0-1 の小数、`flat` の `statValue` (武器・聖遺物) は表示用の値そのまま。混ぜると会心率が 5194% になる
- **名前の取得元が 3 つに分かれている** — キャラ名は `loc.json`、武器名と一部のセット名は `gi/locs.json`、新しい聖遺物セットはアイコン名から set id を取って `gi/relics.json` 経由。片方だけ見ると名前が半分出ない
- **天賦の並びは `SkillOrder` に従う** — `skillLevelMap` の反復順に頼ると通常攻撃と元素爆発が入れ替わる
- **星座による天賦強化は proud id 側にある** — `proudSkillExtraLevelMap` のキーは skill id ではない
- **`affixMap` は 0 始まり** — R5 は `4`
- **ドキュメントと実データで名前が違う** — API ドキュメントは `nameTextHashMap` と書いているが実際は `nameTextMapHash`

## 自動取得間隔のロールポリシー

`genshinRefreshIntervalMinutes`で、本人確認済みの各UIDの自動取得間隔を、そのUIDを連携した利用者の実効ロールポリシーから指定します。1〜1440分の整数、既定10分です。ポリシーに対応していない旧mkでは10分へフォールバックします。対応するmkの管理画面から、ベースポリシーまたは個別ロールの「原神の自動取得間隔（分）」を編集してください。

- ロールの優先度は本体の既存ルールに従います。同じ優先度の設定では短い間隔を採用します。長い間隔を個別ロールで強制する場合は、そのロールの優先度を上げてください。
- 更新確認は1分ごとに行います。最終取得・自動取得の最終試行から指定間隔が経過し、かつEnkaのTTLが切れた場合にのみ取得します。指定した分数ちょうどの更新を保証するものではありません。
- ポリシーの短縮・延長は次の更新確認に反映します。取得前にUIDロック下で所有者・最新ポリシー・TTLを再確認します。
- API不調・ポリシー不正時は自動取得を見送り、古いデータを残します。Enkaへの取得が失敗した場合も試行時刻を保存し、指定間隔より短い間隔で再試行しません。
- 1回のジョブは最大50件を取得します。未到来のUIDは枠を消費せず、失敗したUIDは古い未更新UIDより後ろへ回します。ランキング閲覧で追加取得しない仕様は変わりません。
- 本人確認コードの10分有効期限・送信後最低60秒待機・TTL共有は変更しません。リモートのpeer cacheやマスターデータ更新も別のままです。

Migration 10で`accounts.last_refresh_attempt_at`を追加します。Migration 1〜9は変更せず、既存UID連携・公開設定・ランキングデータを保持します。導入前にプラグインDBを含めてバックアップしてください。
# 公開設定とサーバー内ランキング

この節の公開設定・ランキングとMisaki向けUIは `Misaki-Project/mk-plugin-genshin` の先行実装です。上流の本人確認PRには含めません。

プラグインのfrontend回帰テストは、このリポジトリをmkの `plugins/genshin` に配置した状態で、対応frontendの `third_party/misskey` から `pnpm --filter frontend exec vitest run --config vitest.config.plugins.ts` を実行します。本体frontendの通常テストにはプラグインの有無に依存するテストを混ぜません。

ランキングは「見つける → 原神ランキング」または `/plugin/genshin/rankings` から開けます。Misskey標準の選択UI・ユーザーアイコン・相対時刻を使います。ランキング画面のUID表示は初期状態でオフです。「公開UIDを表示する」を有効にした場合も、利用者が公開を許可したUIDしか表示しません。この画面操作で利用者の公開設定は変わりません。

プロフィールの原神カードを開くと、そのUIDがランキング対象の場合だけ項目別の順位とリンクを表示します。参加を無効にしたUID・凍結や削除で対象外となった利用者・リモート連携は表示しません。カードを閉じると順位とリンクも隠れます。順位は先頭50件に限定せず、ランキング全体の位置です。

プロフィール設定の「原神」で、UIDとステータスメッセージの公開を個別に選べる。設定はそのMisskeyアカウントのすべての連携UIDに適用し、公開APIとpeer応答の両方から非公開項目を除く。既定は従来どおり公開。ゲーム内やEnkaの公開設定は変更しない。他サーバーがすでに受け取った情報は、そのキャッシュ更新まで残る場合がある。

ランキングは **オプトアウト方式（既定で参加）**。参加を無効にすると、本人確認済みの全UIDを集計・表示から除外する。公開設定とは独立しており、UIDを非公開にしたままでも参加できる。ただし、ゲーム内ニックネームと戦績から特定される可能性があるため、匿名化を保証する設定ではない。

削除・凍結済みユーザーは、順位とページ分割の前に除外する。1回の集計では同じDBスナップショットを使い、本体のユーザー情報は100人ずつ取得する。負荷を制限するため候補は最大10,000 UIDとし、超過時は不完全な順位を返さずエラーにする。

`/plugin/genshin/rankings` で、深境螺旋の星・実績・好感度MAX人数・幽境の激戦をUIDごとに表示する。対象はサーバー内の確定済み連携だけで、未確認申請・旧データ・リモートキャッシュは含めない。複数UIDの値を合算しない。同点は同順位。取得済みスナップショットを使用し、一覧閲覧でEnkaへ追加取得しない。

幽境は `playerInfo.stygianId`・`stygianIndex`・`stygianSeconds` を使用し、開催ID別に難易度降順・秒数昇順で順位を付ける。開催ID未指定時は、参加者の有効な記録の最大開催IDを表示する。難易度または秒数がない記録は除外する。深境螺旋は取得時点の公開星数であり、期間を指定した履歴ランキングではない。

Migration 9 で公開・参加設定、表示用のランダムな連携ID、幽境の保存項目を追加する。連携解除後もユーザーの公開・参加設定は維持する。
